TORRENTCONTROL 1.8

ОБНОВЛЕНИЕ
Замените исходные файлы в C:\TorrentMonitor.
Сохраните config.json, credential.xml, state.json, feed-state.json,
а также autoload.json, auto-state.json и файлы *.json.bak, если они уже существуют.
1-Setup.cmd и 6-Enable-autoload.cmd при обновлении с 1.7 повторно запускать не нужно.

СТАТИСТИКА RUTRACKER (ВАЖНО)
Раньше автозагрузка добавляла .torrent с публичным адресом трекера без ключа,
поэтому отдача не начислялась в профиль. Теперь в uTorrent передаётся только
персональный .torrent, скачанный этим компьютером под вашей учётной записью.
9-RuTracker-login.cmd — вход (под пользователем Windows, от имени которого работает монитор).
10-RuTracker-check.cmd — проверка получения персонального .torrent.
Без входа новые фильмы ждут авторизации; публичная версия не добавляется.
Если rutracker.org напрямую не открывается: Hiddify -> "Режим службы" = "Только прокси",
затем 15-RuTracker-connection.cmd (найдёт и проверит локальный порт, запишет rutracker-proxy.txt).
Прокси используется только для запросов TorrentControl к RuTracker; настройки Windows не меняются.
Пароль и cookie зашифрованы DPAPI; на GitHub не передаются.
Уже скачанные раздачи, без повторной загрузки, строго по порядку:
11-Tracker-migration-dry-run.cmd — Dry Run, ничего не меняет (tracker-migration.html);
12-Tracker-migration-one.cmd — одна раздача с подтверждением;
проверить трекер в uTorrent и начисление в профиле RuTracker (README.md);
13-Tracker-migration-verified.cmd — отметить проверку; 14-Tracker-migration-batch.cmd — остальные.

АВТОЗАГРУЗКА
6-Enable-autoload.cmd — включить. Первый запуск исключает текущую подборку.
2-Run-once.cmd — проверить сейчас; далее работает прежнее расписание каждые 15 минут.
7-Disable-autoload.cmd — выключить будущие добавления; текущие раздачи продолжатся.

Только новые темы раздела 252 после включения: WEB-DL/WEB-DLRip/BDRip, Dub/MVO/DVO.
Папка D:\Фильмы\rt-<номер темы>, размер отдельной раздачи не ограничен.
Запас 20 ГиБ плюс место для ещё не скачанных данных текущих заданий на D:.
Задание завершено, только если PROGRESS=1000 и REMAINING=0; при неясных данных добавление ждёт.
Максимум одно добавление за опрос; существующие хеши на всех дисках пропускаются.
Лента и метаданные приходят через GitHub. Python/aria2 на Windows не требуются.
GitHub не гарантирует запуск по расписанию: копия ленты бывает старше 6 часов.
Тогда новые темы ждут следующей копии (лента хранит ~2 недели тем), а очередь
автозагрузки продолжает работать. Возраст копии и причина видны в report.html.

report.html — основной отчёт; films.html — подборка;
auto-downloads.html — журнал автозагрузки; monitor.log — ошибки.
После отправки новое задание ожидает подтверждения пути; повторно не отправляется.
При статусе «Нужна проверка» проверьте задание в µTorrent, затем запустите
8-Review-autoload.cmd. Не стирайте auto-state.json. Автозагрузка не останавливает раздачи.

Удаление отключено. D:/F: отслеживаются; E: архив и C: система исключены из отбора.
WebTLO и общие настройки µTorrent не меняются.
Не меняйте проверенную настройку переноса: только из папки по умолчанию.
µTorrent должен быть запущен в одном экземпляре на этом компьютере.
Пользователь Windows должен оставаться вошедшим; блокировка/отключение RDP допустимы.
Полная документация — README.md.
