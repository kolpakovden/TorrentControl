МОНИТОР ВРЕМЕННЫХ РАЗДАЧ — первый этап, только отчёт

1. Распакуйте всю папку на КОМПЬЮТЕР С РАЗДАЧАМИ, например C:\TorrentMonitor.
2. Запустите 1-Setup.cmd обычным двойным щелчком под своей учётной записью Windows.
3. Нажмите Enter для адреса http://127.0.0.1:9090 (если µTorrent на этом же компьютере).
4. В окне входа укажите admin и пароль WebUI. Пароль никуда отправлять не нужно.
5. После проверки создаётся отчёт report.html и задание TorrentMonitor-DF на каждые 15 минут.

Компьютер должен быть включён, µTorrent запущен, пользователь Windows — вошедшим в систему.
Блокировка экрана и отключение сеанса удалённого рабочего стола не равны выходу из Windows.
При выходе из учётной записи задание не выполняется. После входа работа возобновляется.
После настройки не перемещайте папку; иначе повторите настройку по новому пути.

Отчёт: report.html (открыть браузером, обновить F5), таблица: report.csv.
Для проверки вручную: 2-Run-once.cmd. Журнал работы: monitor.log.
Если настройка не удалась, пришлите текст из окна или monitor.log.
Не присылайте credential.xml: пароль в нём защищён средствами Windows и привязан к пользователю/компьютеру.

ПРАВИЛА
Версия 1.5: подборка раздела 252 в films.html; ссылка из report.html. Автозагрузка отключена.
Первый запуск — исходный список, затем отмечаются впервые замеченные темы.
Дата updated в ленте не гарантирует дату создания темы. Ошибки ленты не останавливают мониторинг.
Сохраняйте feed-state.json при обновлении. Если нужен прокси, адрес задаётся в feed-proxy.txt.
Версия 1.4: отслеживаются все папки на D: и F:, включая D:\Хранитель.
Весь E: — постоянное хранение, исключён. C: — системный, исключён.
Обрабатываются только раздачи с абсолютным путём на D: или F:.
Версия 1.1: если API не сообщает путь, монитор читает локальный resume.dat и сопоставляет по info-hash, не по названию.
Поиск: %APPDATA%\uTorrent\resume.dat и resume.dat рядом с запущенным utorrent.exe.
При другом расположении создайте resume-path.txt рядом с Monitor.ps1 и вставьте полный путь к нужному resume.dat.
Сам resume.dat не изменяется. µTorrent периодически сохраняет его, поэтому новые пути могут появляться с задержкой.
При неизвестном или неоднозначном пути раздача не становится кандидатом. Монитор необходимо запускать на компьютере с µTorrent.
Другие диски исключены. Программа не читает содержимое раздач и не удаляет/останавливает их.
Кандидат: полностью скачана, 30 дней наблюдаемого хранения, 14 дней без замеченного спроса.
Возраст для надёжности отсчитывается с начала мониторинга, а не предполагается по старой дате.
Спрос: прирост суммарной отдачи, текущая отдача или скачивающие по данным клиента.
Количество сидов не ограничивает включение в кандидаты.
Перерыв между успешными наблюдениями более часа сбрасывает 14-дневный срок.
Остановка, пауза, ошибка, проверка файлов, неполная загрузка также сбрасывают срок тишины.
Смена пути или сброс счётчика отдачи начинает наблюдение заново.
Данные трекера могут быть неполными: «не замечен спрос» не доказывает отсутствие желающих скачать.
Отчёт показывает время последнего успешного обновления. При ошибке подключения старый отчёт остаётся.
История state.json компактная: хранит счётчики и временные отметки, а не все опросы.

ОСТАНОВКА
Откройте «Планировщик заданий» Windows, найдите TorrentMonitor-DF и отключите его.
Это остановит только монитор, не µTorrent и не WebTLO.

Совместимость: Windows PowerShell 5.1. Python и дополнительные программы не требуются.
Настоящий клиент пользователя из среды разработки недоступен; первый запуск проверяет подключение.
API: https://github.com/bittorrent/webui/wiki/Web-UI-API
Авторизация: https://github.com/bittorrent/webui/wiki/TokenSystem
