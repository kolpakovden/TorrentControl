## RuTracker: персональные `.torrent` и статистика отдачи

TorrentControl использует RuTracker для загрузки новых фильмов из [раздела 252](https://rutracker.org/forum/viewforum.php?f=252). Для новых заданий клиенту передаётся **персональный `.torrent`**, скачанный под вашей учётной записью, а не публичный магнитный файл без ключа.

## Почему это важно

Публичные метаданные позволяют проверить хеш, имена и размеры файлов, но публичный адрес трекера не привязан к учётной записи RuTracker. TorrentControl получает отдельный персональный `.torrent` через авторизованную сессию и проверяет его infohash, формат и принадлежность трекера. Если файл получить нельзя, новая раздача **не добавляется** и ожидает устранения причины.

## Настройка

1. Под тем же пользователем Windows, от которого запускается планировщик, выполните **`9-RuTracker-login.cmd`**. CAPTCHA вводится человеком, автоматически не обходится.
2. Запустите **`10-RuTracker-check.cmd`**. Успешная проверка подтверждает получение корректного персонального `.torrent`; она **сама по себе не доказывает начисление отдачи**.
3. Если сайт недоступен, выполните **`15-RuTracker-connection.cmd`**. Скрипт проверяет доступные маршруты и записывает выбранный прокси только после подтверждения. Возможен локальный прокси Hiddify; системные настройки, браузер и µTorrent не перенастраиваются.
4. Если сайт доступен в Firefox, но недоступен клиенту TorrentControl, персональный `.torrent` можно скачать вручную и использовать **`16-Import-personal-torrent.cmd`**. Импорт проверяет соответствие записи и infohash.

## TLS и сторонние зависимости

На Windows 10 штатный транспорт PowerShell 5.1 не обеспечивает требуемое для данного маршрута соединение TLS 1.3 с RuTracker. Поэтому в комплект включена **BouncyCastle.Cryptography 2.7.0**. Папка `lib\bouncycastle\2.7.0` должна находиться рядом со скриптами и не должна изменяться: DLL проверяется по SHA-256 перед загрузкой.

Происхождение, контрольные суммы и лицензию см. в составе релизного ZIP: `lib/bouncycastle/2.7.0/SOURCE.txt` и `lib/bouncycastle/2.7.0/LICENSE.md`. См. также [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Конфиденциальность

- Данные входа и cookie сессии хранятся локально, зашифрованными Windows DPAPI для текущего пользователя.
- Персональные `.torrent` находятся в `%LOCALAPPDATA%\TorrentControl\personal`.
- GitHub получает только публичную ленту и метаданные, **не** получает логин, пароль, cookie или персональные ключи.
- Ключ трекера не должен попадать в отчёты и журналы; если вы публикуете скриншоты, отдельно проверьте, что на них нет секретов.
- Для работы с DPAPI и запланированным заданием должна использоваться одна и та же учётная запись Windows.

## Уже существующие раздачи

Для раздач, ранее добавленных с публичным трекером, предусмотрена отдельная безопасная перепривязка **без перекачивания файлов**:

| Команда | Назначение |
| --- | --- |
| `11-Tracker-migration-dry-run.cmd` | Только проверить кандидатов |
| `12-Tracker-migration-one.cmd` | Перепривязать одну раздачу с явным подтверждением |
| `13-Tracker-migration-verified.cmd` | Подтвердить проверку трекера и учёта отдачи |
| `14-Tracker-migration-batch.cmd` | Обработать остальные после проверки |
| `17-Check-personal-migration.cmd` | Диагностика кандидатов и персональных файлов |

Перепривязка допускается только для раздач, происхождение которых подтверждено TorrentControl. Ручные и посторонние раздачи не должны изменяться. Перед пакетной операцией обязательно выполните Dry Run и проверку одной раздачи. Не публикуйте персональные адреса announce.
