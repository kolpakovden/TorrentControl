# TorrentControl

Монитор временных раздач µTorrent для Windows. Текущая версия: **1.6**.

Получает статистику через WebUI, сохраняет историю и формирует HTML/CSV-отчёт.
**Сейчас работает только наблюдение: удаления, остановки и добавления торрентов нет.**

## Запуск

1. Скопировать файлы на компьютер с µTorrent, например в `C:\TorrentControl`.
2. Запустить `1-Setup.cmd` под обычной учётной записью Windows.
3. Для µTorrent на этом же компьютере оставить `http://127.0.0.1:9090`.
4. Ввести данные WebUI. Пароль сохраняется локально через Windows DPAPI.
5. Проверить `report.html`. Задание `TorrentMonitor-DF` запускает опрос каждые 15 минут.

Требуется Windows PowerShell 5.1. Пользователь должен оставаться вошедшим в Windows;
блокировка экрана или отключение RDP допустимы. Выход из учётной записи останавливает запуск задания.
Для разового опроса использовать `2-Run-once.cmd`.

## Новые публикации фильмов

Версия 1.6 получает публичную копию ленты из `data/forum-252.json` этого репозитория.
GitHub Actions (`Refresh film feed`) запрашивает исходную Atom-ленту раздела 252
дважды в час, на 17-й и 47-й минутах. Расписание GitHub может задерживаться;
доступен ручной запуск через Actions → Refresh film feed → Run workflow.
На компьютере с раздачами нужен доступ к `raw.githubusercontent.com`.
Старый `feed-proxy.txt` больше не используется. Пароли и данные µTorrent в GitHub не отправляются.
Копии старше 6 часов отклоняются с `MirrorStaleOver6Hours`; последняя успешная подборка сохраняется.
Неудачный запуск workflow не заменяет сохранённую копию. В публичном репозитории GitHub
может отключить расписание после 60 дней без активности; его можно включить в Actions.
Результат: `films.html` и `films.csv`, ссылка из основного отчёта.
В подборке отдельно показано время получения исходной ленты GitHub в UTC.

Первый успешный запуск фиксирует исходный список; новые ID тем при дальнейших проверках
отмечаются как впервые замеченные. Записи текущей ленты сравниваются по хешу со всеми
торрентами µTorrent, включая E:. Автоматического скачивания нет.

В полученной ленте есть `updated`, но нет `published`: её дата не выдаётся за доказанную дату
создания темы. Лента ограничена и не заменяет полный каталог; обновление старой темы может
впервые появиться у наблюдателя. Разные релизы одного фильма не объединяются.
История ID хранится в `feed-state.json`; сохраняйте файл при обновлении.

Учётные данные RuTracker не запрашиваются. Ошибка получения копии не прерывает мониторинг раздач.
GitHub успешно получил 50 записей в первом запуске workflow. Доступ к копии с компьютера
с раздачами проверяется запуском `2-Run-once.cmd`.

Обновление до 1.6: заменить исходные файлы в прежней папке, сохранив `config.json`,
`credential.xml`, `state.json` и `feed-state.json`. Повторная настройка задания не требуется.

## Подготовка автозагрузки

Выбрана папка `D:\Фильмы`, без ограничения размера одной раздачи.
Пользователь сообщил о 340 ГБ свободного места; перед загрузками нужно проверять
фактическое свободное место и учитывать ещё не скачанные данные текущих заданий.
Автозагрузка пока не включена: сначала требуется проверить настройки µTorrent 2.2.1.
Запустите `3-Check-download-folder.cmd` в установленной папке монитора.
Проверка читает через WebUI только настройки, выводит разрешённый список параметров
папок и свободное место D:. Настройки и раздачи не меняются, пароль не выводится.
Результат нужен для проверки папки загрузки и переноса завершённых файлов.

После проверки настроек доступен `4-Test-download-path.cmd`: он создаёт короткий
тестовый текст в `D:\Фильмы` и добавляет его через `/DIRECTORY` как приватный торрент
без трекеров. Успех нужно подтвердить в µTorrent: путь на D: и готовность 100%.
Тест не меняет общие настройки и не включает автозагрузку фильмов.
Пользователь подтвердил тест `/DIRECTORY` на µTorrent 2.2.1 build 25534: файл
сохранился в `D:\Фильмы`, готовность 100%, статус «Раздаётся».

Получение метаданных по magnet проверено в GitHub Actions (`Test magnet metadata only`).
Первый тест через один DHT не получил метаданные; повтор с оригинальным публичным
трекером из ленты успешно получил `.torrent`: хеш совпал, 2 файла, 1 473 741 793 байта.
Используются `aria2 --bt-metadata-only=true --bt-save-metadata=true`: данные фильма
не скачиваются. Результат разового теста — `data/metadata-test.json`.
`TorrentMetadata.cs` повторно проверяет infohash и точный размер на Windows; проверка
успешно пройдена на полученном файле. Это ещё не проверка безопасности путей внутри torrent.

Полный цикл автозагрузки пока не включён. Остаётся связать новые темы, фильтры,
проверку путей и свободного места с учётом незавершённых загрузок, журнал добавлений
и передачу проверенного `.torrent` в µTorrent. Разовый тест не добавляет торренты в клиент.

## Правила хранения

- Временные раздачи: **все папки на D: и F:**, включая `D:\Хранитель`.
- **Весь диск E:** — постоянное хранение, исключён из отбора.
- **Диск C:** — системный, исключён из отбора.
- Остальные диски также не участвуют в отборе: разрешены только D: и F:.
- Кандидат: полностью скачан, наблюдаемое хранение не менее 30 дней,
  не менее 14 дней без прироста отдачи и замеченных скачивающих.
- Количество сидов не препятствует отбору, в том числе если пользователь последний сид.
- Перерыв между проверками более часа, остановка, ошибка или неполная загрузка
  сбрасывают период отсутствия спроса. Смена пути или сброс счётчиков начинают наблюдение заново.
- Данные о спросе — наблюдения клиента; они не гарантируют отсутствие желающих скачать.

В старых µTorrent путь может отсутствовать в WebUI. Тогда монитор читает локальный
`resume.dat` из `%APPDATA%\uTorrent` и папки запущенного клиента, сопоставляя раздачи по info-hash.
Можно указать полный путь к файлу в `resume-path.txt`. Файл клиента не изменяется.
Неопределённые или неоднозначные пути не участвуют в отборе.

## Обновление и диагностика

Обновлять исходные файлы в прежней папке, сохраняя локальные config.json,
credential.xml и state.json. После перемещения папки повторить настройку задания.
Пароль и локальные данные исключены через `.gitignore`.

Если время отчёта не меняется, проверить `monitor.log` и задание `TorrentMonitor-DF`
в Планировщике: время следующего запуска, код результата и путь во вкладке «Действия».
Код 0x0 подтверждает успешное завершение процесса, но следует также проверить обновление нужного отчёта.

## Проверено

На пользовательском µTorrent 2.2.1 подтверждено чтение 426 раздач и определение всех путей:
151 раздача на D:/F: и 275 на других дисках; неизвестных путей нет (подтверждено на версии 1.4).
В версии 1.4 исключение папки `D:\Хранитель` снято; эти две раздачи снова отслеживаются.
Подтверждены накопление отдачи и корректные русские названия.
24 октября 2026 года подтверждён автоматический запуск: без ручного запуска скрипта время отчёта изменилось с 11:24:21 на 11:28:10, а счётчики отдачи выросли. Время приведено как отображалось на компьютере с раздачами. Пользователь только обновил страницу клавишей F5. Длительная стабильность ещё наблюдается.

Локальные проверки охватывали правила истории, бинарные хеши, UTF-8, повреждённый resume.dat,
старый формат API, генерацию отчёта и отбор по дискам.
