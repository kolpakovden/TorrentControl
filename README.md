# TorrentControl

Монитор временных раздач µTorrent для Windows. Текущая версия: **1.4**.

Получает статистику через WebUI, сохраняет историю и формирует HTML/CSV-отчёт.
**Сейчас работает только наблюдение: удаления, остановки и добавления торрентов нет.**

## Запуск

1. Скопировать файлы на компьютер с µTorrent, например в `C:\TorrentControl`.
2. Запустить `1-Setup.cmd` под обычной учётной записью Windows.
3. Для µTorrent на этом же компьютере оставить `http://127.0.0.1:9090`.
4. Ввести данные WebUI. Пароль сохраняется локально через Windows DPAPI.
5. Проверить `report.html`. Задание `TorrentMonitor-DF` запускает опрос каждые 15 минут.

Требуется Windows PowerShell 5.1. Пользователь должен оставаться вошедшим в Windows;
блокировка экрана или отключение RDP допустимы. Выход из учётной записи останавливает запуск задания.
Для разового опроса использовать `2-Run-once.cmd`.

## Правила

- Временные раздачи: **все папки на D: и F:**, включая `D:\Хранитель`.
- **Весь диск E:** — постоянное хранение, исключён из отбора.
- **Диск C:** — системный, исключён из отбора.
- Остальные диски также не участвуют в отборе: разрешены только D: и F:.
- Кандидат: полностью скачан, наблюдаемое хранение не менее 30 дней,
  не менее 14 дней без прироста отдачи и замеченных скачивающих.
- Количество сидов не препятствует отбору, в том числе если пользователь последний сид.
- Перерыв между проверками более часа, остановка, ошибка или неполная загрузка
  сбрасывают период отсутствия спроса. Смена пути или сброс счётчиков начинают наблюдение заново.
- Данные о спросе — наблюдения клиента; они не гарантируют отсутствие желающих скачать.

В старых µTorrent путь может отсутствовать в WebUI. Тогда монитор читает локальный
`resume.dat` из `%APPDATA%\uTorrent` и папки запущенного клиента, сопоставляя раздачи по info-hash.
Можно указать полный путь к файлу в `resume-path.txt`. Файл клиента не изменяется.
Неопределённые или неоднозначные пути не участвуют в отборе.

## Обновление и диагностика

Обновлять исходные файлы в прежней папке, сохраняя локальные config.json,
credential.xml и state.json. После перемещения папки повторить настройку задания.
Пароль и локальные данные исключены через `.gitignore`.

Если время отчёта не меняется, проверить `monitor.log` и задание `TorrentMonitor-DF`
в Планировщике: время следующего запуска, код результата и путь во вкладке «Действия».
Код 0x0 подтверждает успешное завершение процесса, но следует также проверить обновление нужного отчёта.

## Проверено

На пользовательском µTorrent 2.2.1 подтверждено чтение 426 раздач и определение всех путей:
151 раздача на D:/F: и 275 на других дисках; неизвестных путей нет (подтверждено на версии 1.4).
В версии 1.4 исключение папки `D:\Хранитель` снято; эти две раздачи снова отслеживаются.
Подтверждены накопление отдачи и корректные русские названия.
24 октября 2026 года подтверждён автоматический запуск: без ручного запуска скрипта время отчёта изменилось с 11:24:21 на 11:28:10, а счётчики отдачи выросли. Время приведено как отображалось на компьютере с раздачами. Пользователь только обновил страницу клавишей F5. Длительная стабильность ещё наблюдается.

Локальные проверки охватывали правила истории, бинарные хеши, UTF-8, повреждённый resume.dat,
старый формат API, генерацию отчёта и отбор по дискам.
